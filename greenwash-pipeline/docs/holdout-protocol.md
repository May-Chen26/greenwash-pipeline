# v0.3 独立考核协议

目的：区分开发样本上的修复与新报告上的泛化表现。

1. 在接触下一份报告前冻结源码版本与 SHA-256 清单；运行环境记录 Python、Poppler、PyMuPDF 版本。
2. 收到新报告后，以未修改的 v0.3 执行第一次提取，保留原始输出、文档哈希、警告和运行时间。第一次运行错误也是结果，不得隐藏。
3. 阅读原文，预先列出人工核验的页面、指标、声明和口径。数值金标准应覆盖所选页的全部目标单元格，包括模型漏提的单元格；不得只核验模型找到的内容。
4. 使用 evaluate 脚本测量标注页内 metric/year/unit/value 完全匹配的 precision/recall，同时单独核验主体、边界、Scope2 方法、原文追溯。数值匹配不是语义正确率。
5. 声明人工标注至少覆盖结果、未来目标、强度/绝对量、缺少证据、第三方目标、否定或条件表述。记录完整性、年份、指标、主体以及漏提/误提，声明评估暂需人工进行。
6. 分别报告正确、错误、漏提、弃权；说明样本数，不将一份报告的结果泛化到所有公司。不把输出数量称为召回率。
7. 如首轮失败，先报告并保留失败结果，再修复为下一版本。修复后成绩不得冒充原版独立考核成绩。

v0.3 不设无数据支持的上线合格阈值；数值、语义、边界与声明核验分别验收。自动评分仍禁用。
